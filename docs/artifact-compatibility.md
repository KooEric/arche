# Snapshot and evaluation compatibility

| Artifact | Current writer | Reader contract |
|---|---|---|
| inventory.json, graph.json, changes.json | `schema_version: "1.0"` | Accept RC `"0.1"` and current `"1.0"`. Legacy documents without the field follow the original structural checks. Reject other explicit versions. `graph.json` edges may carry `kind: "REFERENCES"` (a SQL file path written as text in a parsed file; `rule` is `relative`, `root` or `suffix`, `reason` is `dynamic`, `ambiguous` or `not_found`) and file nodes may carry `lang: "sql"`. Both are additive; readers that only follow `IMPORTS` skip them. `graph.json` edges may also carry `kind: "READS"` (a SQL file reading a table another SQL file writes; `table` holds the normalized name, `rule` is `name` or `table_name`, `reason` is `dynamic` or `ambiguous`), and the document gained the optional `external_tables` list (`from`, `table`, `line`) for tables no scanned SQL file writes. Both are additive. The document also gained the optional `written_tables` list (`table`, `from`, `line`): every table a scanned SQL file writes, at its first line, excluding temporary and run-time names. It is additive. |
| `map.json` (agent-written), `atlas.json`, `descriptions/*.json` | integer `version: 1` / `schema_version: 1` | `map.json` names parts, cited edges and flows; `map.py` checks it against the snapshot and writes `atlas.json`, the only input of `map.html`. `atlas.json` carries `inventory_sha256`; render refuses one from another snapshot. `graph.json` gained the optional `http_routes` list. `map.py` also writes `map.lock.json` (`schema_version: 1`: hashes of cited line ranges and parsed files, and the route keys), and line sketches of described or cited files), which `carry.py` needs to move a map to a later scan; `carry.json` is its report. `map.json` may carry `screens`; `atlas.json` carries `screens`, `changes` and `findings` lists. `atlas.json` link `kind` may be `reference` or `read` (part links counted from `REFERENCES` and `READS` edges) in addition to `import`, `http`, `package` and `cited`; additive. |
| tour and exported tour envelope | integer `version: 1` | Step IDs, source-relative paths, inclusive line ranges and whole-file SHA-256 are required for evidence. Optional screens, focused HTTP candidates, the tour `title` and `summary`, and step `title`, `note` and `range_sha256` are additive. `range_sha256` is the SHA-256 of the cited lines joined by newlines; with it, a step whose file changed elsewhere is re-anchored to the same lines instead of being rejected. A verified tour can be rendered again against the matching checkout. |
| audit.json | integer `schema_version: 1` | Bind captured findings to repository revision, inventory digest and internal-export assumptions before comparing. |
| Repair capture and comparison JSON | integer `schema_version: 1` | Preserve immutable fixture identity, execution outcome and derived checks. Replay a repair against its recorded baseline; a fixture change requires retaining the old skill version. |
| Understanding study | integer manifest version 1, JSONL trials | Keep the golden, manifest, prompt template, input hashes and raw responses with the capture. Legacy step-local conditions and top-level conditions are both scored. |
| profile.json | integer `profile_version: 1` | Written by `data_profile.py`. Carries `inventory_sha256`; render refuses a profile of another snapshot. Holds data folder roots (absolute paths, kept out of report.html), datasets with column summaries, and `matches` (`verified` with `rule: map`, `inferred` with `rule: path` or `table_name`), `unresolved` (`reason: ambiguous`), `orphan_datasets` and `tables_without_data`. String values appear only under `top_values` with `--show-values`, never for a column marked `sensitive`. A dataset's reader is "stdlib" or "library"; the library name (pyarrow or duckdb) is recorded in run.json as parquet_reader, so profile.json does not depend on the machine. A dataset record may carry the optional keys `header_suspect` and `columns_truncated`, and the document carries `truncated` when discovery stopped at a file or dataset limit. |

In graph.json `http_connections`, requests may carry an optional `host` and candidate routes an optional `prefix_unknown`, and the reason values `method_and_path_pattern`, `external_host`, `route_prefix_unknown` and `variable_only_route` were added; older readers can ignore them.

Snapshot identity covers repository name, revision, dirty state and scanned file entries. The 1.0 graph's SHA-256 uses UTF-8 JSON of the file entries sorted by path and key, with two-space indentation and a terminating newline. The checkout root stays out of that digest. RC graphs instead compare the available file-node hashes. Unsupported files have only their recorded metadata; changing an unscanned file is outside the content guarantee. Live source-backed tours also recheck the cited file hashes. Git status is a separate consistency signal.

To migrate an RC run, retain the original directory and recreate the snapshot with the new helpers in a new directory at the same revision. Use the old tour if its hashes still validate. An offline evaluation rescore uses the archived raw answers and the selected scorer version. Record that version when comparing scores across releases. New optional fields can be ignored by older consumers; a breaking change requires a new schema identifier and an explicit migration procedure.
